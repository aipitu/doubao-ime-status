# 验证记录与真机验收

**中文** | [English](VALIDATION.en.md)

## 本会话可执行的验证

- 0.1.1 Linux Swift 执行纯状态机/坐标测试：50 项通过（包括切焦点保持已知状态和 block caret）。
- ARM64 和 Intel macOS 交叉编译、LLD 链接、包结构/签名：实际结果见 `BUILD-REPORT.md`。
- 不把「编译成功」写成「在 macOS 已运行」。Linux 不具备 AppKit、WindowServer、TCC 或真实豆包输入法，不能执行原生 GUI 验收。

## 在 macOS 13+ 验收

1. 解压 ZIP，把应用移到 `/Applications`，打开。确认菜单栏出现 `?`，Dock 无图标；设置可打开和关闭，再从菜单重开。
2. 授权辅助功能和输入监控。设置中应显示辅助功能已授权、输入监听运行中。
3. 选择豆包，实际输入拼音触发候选窗，确认显示「中」。独立 Shift 切英文，确认显示「A」，再切回中文。
4. 连续输入大写字母、Shift+方向键、Cmd+Shift 快捷键、Shift+鼠标与滚动、左右 Shift 同按，不能误翻转。快速连按 Shift 时看 AX 校准是否纠正推断。
5. 已知状态时切换应用或 Space，输入源未变则保持显示并复核，不能无条件变问号；重新选中豆包或唤醒时，实际证据到来后校准。手动校准不能向前台发送任何输入。
6. 分别在 VS Code、Cursor、Terminal、iTerm、Chrome、Safari、JetBrains 中输入、点击、上下移动 caret、滚动、选择一段文字。通过设置「位置」信息判断是否真正拿到 AX caret。不支持时必须跟随鼠标，不能留在旧应用位置。
7. 切换 Follow Mouse。快速/缓慢移动和静止；指示器不应跳到旧 caret。修改方向、正负 offset、精确数值、文字、颜色、字体、透明度、背景、圆角，确认预览和指示器立即变化。
8. 在指示器覆盖处点击/拖动/选择，确认事件落到原应用，输入焦点不丢失。
9. 双屏测试：副屏位于左、右、上、下；不同缩放/Retina、菜单栏主屏切换、屏幕边缘、断开显示器。位置不得被错误 Y 翻转或留在不存在的屏幕。
10. Mission Control 切 Space、进入/退出全屏、切换全屏桌面。安全输入框与锁屏隐藏，解锁恢复；停用后悬浮消失且无后台 AX 查询。
11. 菜单启用登录启动，在系统「登录项」核实条目，注销/登录验证；关闭后再次登录不得启动。

## 性能测量（待填）

用 Activity Monitor 或 Instruments，在上述应用分别测量 60 秒空闲、打字、持续移动鼠标及停用状态。记录系统版本、芯片、豆包版本、应用版本、平均/峰值 CPU 与唤醒数。建议验收目标为空闲平均 CPU < 1%，但本会话没有测出或承诺这个数值。

若 AX 慢调用影响跟随，记录诊断原因和应用版本；不启用全树扫描补救。若未知无法校准，先确认豆包模式提示是否启用、是否能被辅助功能读取，以及输入监控是否运行。状态为「独立 Shift 推断」时不应称作已直接读取豆包内部状态。
